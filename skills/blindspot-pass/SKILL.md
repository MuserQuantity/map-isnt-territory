# blindspot-pass（盲区扫描）

针对象限：**Unknown Unknowns**——用户没考虑过的东西、不知道该问什么、不知道「好」能有多好。

核心思路：agent 搜代码库和互联网远快于人，对多数领域的了解也超过普通人；让 agent 先替用户把疆域看一遍，把盲区翻译成用户能理解、能决策的语言。**最终目标不是替用户做，而是让用户之后能 prompt 得更好。**

## 触发信号

- 用户字面说「blindspot pass」「盲区扫描」「unknown unknowns」。
- 要在不熟悉的代码库区域写功能（「我要加一个 auth provider，但对这个代码库的 auth 模块一无所知」）。
- 进入陌生的专业领域（「我不知道什么是 color grading，但需要给视频调色」）。
- 用户希望「先学会怎么 prompt 你，再开始干」。

## 前置输入（缺了就先问）

1. 用户想完成什么（哪怕很粗糙）。
2. 用户已知什么、经验到什么程度——决定讲解深浅和报告重点。
3. 扫描范围：代码库的哪些部分 / 领域的哪个子问题。

## 工作流

1. **探索疆域**（能并行就并行）：
   - 代码库侧：相关模块结构、既有实现与惯例、历史决策痕迹（git log、注释、相邻用法）、已知坑（TODO / FIXME / workaround）。
   - 领域侧：必要时搜索领域知识、术语、评价标准、常见失败模式。
2. **产出盲区报告**（Markdown，模板见下）。
3. **教学讲解**：按用户水平解释报告中每一项为什么与其任务相关，允许追问。
4. **改写 prompt**：基于补齐的认知，给出 2~3 个「现在你可以这样 prompt 我」的具体建议——把新知识固化成 Known Knowns。

## 盲区报告模板

```markdown
# 盲区报告：<主题>

## 你需要知道的关键概念
- <概念>：<一句话解释 + 为什么影响你的任务>

## 这个代码库/领域的既有惯例与历史决策
- <惯例>：<在哪里、为什么存在、违背它的代价>

## 常见坑与失败模式
- <坑>：<症状、成因、如何避开>

## 「好」长什么样
- <评价标准 / 可参照的范例>

## 你应该问但还没问的问题
- <问题>（建议回答后再动手）

## 建议的下一步 prompt
> <可直接使用的 prompt 草稿>
```

## 反模式

- 写成领域百科全书：只保留**与用户任务相关**的盲区。
- 只列问题不教学：目标是用户读完能做决策、能 prompt 得更好。
- 跳过用户背景直接扫：不知道用户已知什么，就分不清哪些才是盲区。
- 扫完直接动手实现：盲区扫描的产出是认知和更好的 prompt，实现是下一步的事。

## 示例 prompt（用户视角）

> 「我要加一个新的 auth provider，但我对这个代码库的 auth 模块一无所知。帮我做一个 blindspot pass，找出我的 unknown unknowns，帮我之后更好地 prompt 你。」

> 「我不懂 color grading 但需要给这条视频调色。教我理解这个领域里我的 unknown unknowns，让我之后能 prompt 得更好。」
